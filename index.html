Frequently asked questions

Everything you need to know about how Undupe handles your files.

Does Undupe upload my files to any cloud server?

No. Absolutely nothing leaves your device. Undupe runs 100% locally within your browser tab using Web Workers and local cryptographic APIs. There is no backend server, no database, and zero tracking analytics.

Will it automatically delete my original files?

By default, Undupe runs in Copy Mode, which leaves your original files completely untouched and writes organized clean copies into your output folder. If you opt into Move Mode, originals are deleted only after the app verifies that the new file was written cleanly and matches the source size exactly.

What counts as an exact duplicate?

Undupe compares files by their cryptographic SHA-256 byte-for-byte content fingerprint. Filenames, folder paths, and file creation timestamps can be completely different, but if the underlying content bytes match, Undupe identifies them as duplicates.

How does it handle massive multi-terabyte drives?

Undupe uses a 3-tiered hashing architecture to minimize disk I/O. First, files are grouped by exact size. Unique file sizes are immediately ignored. Next, candidate duplicates undergo a quick partial head/tail fingerprint scan. Full SHA-256 hashing is only performed on actual candidate groups, keeping your memory usage light and processing speeds fast.

Why is Chrome or Edge required on Desktop?

Undupe relies on the W3C File System Access API (`showDirectoryPicker`), which allows web apps to directly read and write folders on desktop drives without uploading files through HTML forms. Currently, Chromium-based desktop browsers (Google Chrome, Microsoft Edge, Brave) support this API, whereas Safari and Firefox do not yet support it.
